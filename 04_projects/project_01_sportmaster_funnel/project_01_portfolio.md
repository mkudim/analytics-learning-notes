# Executive Dashboard: Воронка онлайн-продаж e-commerce

## Контекст проекта
**Краткое описание проекта**

Проект выполнен на данных e-commerce направления компании Спортмастер — крупного омниканального ритейлера спортивных товаров, работающего через сайт, мобильное приложение и сеть офлайн-магазинов.

Бизнес-модель компании предполагает:
* привлечение пользователей в цифровые каналы,
* формирование спроса через каталог товаров,
* конвертацию интереса в покупки через корзину и оформление заказа.

Анализ проводился на основе clickstream-данных пользователей цифровых каналов (сайт и мобильное приложение).

Период анализа:
01.06.2024 — 21.06.2024
(последний день содержит неполные данные)

Ключевые бизнес-метрики:
* количество заказов (Orders)
* количество пользователей (Users)
* конверсии воронки (View → Cart, Cart → Order, View → Order)

**Цель анализа**

Целью проекта было:
* создать executive-дашборд для мониторинга здоровья e-commerce воронки,
* обеспечить быстрый контроль ключевых показателей для уровня CEO,
* выявлять ранние сигналы проблем без углубления в операционные детали.

## Область анализа

В рамках проекта были рассмотрены следующие направления:

**Направление 1:** Общая динамика бизнеса
Оценка стабильности заказов и пользовательского потока.

**Направление 2:** Верх воронки (интерес к продукту)
Анализ конверсии от просмотра карточки товара к добавлению в корзину.

**Направление 3:** Нижняя часть воронки (покупка)
Анализ эффективности перехода от корзины к оформлению заказа.

**Направление 4:** Сквозная эффективность воронки
Оценка итоговой конверсии View → Order как ключевой метрики e-commerce.

## Структура данных и первичные проверки

### Обзор структуры данных

Используемая база данных включает одну основную витрину:

events_v — таблица событий пользователей
Содержит данные о просмотрах товаров, добавлениях в корзину и оформлении заказов.

Общий объём данных: ~7 000 000 записей
Уровень детализации: event-level (одно событие = одна строка)

### Связи и логика данных

Каждая запись соответствует событию пользователя в цифровом канале.
Воронка строится на основе флагов событий:
* просмотр товара,
* добавление в корзину,
* создание заказа.

Данные не нормализованы по сущностям, что характерно для clickstream-логов.

## Ключевые метрики и определения

В проекте использовалась единая версия расчёта метрик:

Orders
```Количество событий с флагом create_order = true.```

Users
```Количество уникальных user_id за день.```

CR View → Cart

```Add to Cart / Views```


CR Cart → Order

```Orders / Add to Cart```


CR View → Order

```Orders / Views```


Важное допущение:
Метрики считаются на уровне событий, а не уникальных заказов.

## Краткое резюме для стейкхолдеров

Ключевые выводы анализа:
* Бизнес демонстрирует стабильное количество заказов день-ко-дню.
* Пользовательский поток сохраняется на сопоставимом уровне.
* Основные потери происходят на этапе View → Cart, а не в checkout.
* Нижняя часть воронки (Cart → Order) работает стабильно.

Executive-вопрос:
«Нужно ли вмешательство?»

Существенных аномалий не выявлено, рекомендуется мониторинг верхней части воронки.

## Детальный разбор инсайтов
**Направление 1:** Общая динамика бизнеса

*Инсайт 1:*
Количество заказов за 20.06.2024 составило ~12,6 тыс., что сопоставимо с предыдущим днём (19.06).

*Инсайт 2:*
Изменения day-over-day находятся в пределах нормальной вариативности и не сигнализируют о резких сбоях.

**Направление 2:** Верх воронки (View → Cart)

*Инсайт 1:*
CR View → Cart находится в диапазоне 15–18%, что соответствует ожиданиям для крупного e-commerce.

*Инсайт 2:*
Небольшое снижение конверсии day-over-day может указывать на:
* изменения в ассортименте,
* влияние промо,
* UX-факторы карточек товаров.

**Направление 3:** Нижняя часть воронки (Cart → Order)

*Инсайт 1:*
CR Cart → Order стабильно выше CR View → Cart, что является нормальным паттерном поведения пользователей.

*Инсайт 2:*
Checkout и процесс оплаты не являются основным источником потерь.

## Рекомендации и следующие шаги

На основании анализа рекомендуется:
* Product / UX:
    провести диагностику карточек товаров с низкой конверсией View → Cart.

* Аналитика:
    расширить анализ сегментацией по категориям товаров.

* Бизнес:
    использовать текущий дашборд для регулярного executive-мониторинга.

## Допущения и ограничения

В ходе анализа были приняты следующие допущения:
* последний день данных (21.06) является неполным и исключён из KPI,
* отсутствуют данные о выручке и стоимости заказов,
* анализ ограничен уровнем событий без user-journey.

Эти ограничения не мешают решению executive-задач, но ограничивают глубину продуктового анализа.
