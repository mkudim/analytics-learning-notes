Executive Dashboard: E-commerce Funnel Health

(Sportmaster — учебный проект)

1. Контекст проекта

Роль: BI / Product Analyst
Домен: E-commerce
Цель:
Создать executive-дашборд для CEO, который позволяет за 10–15 секунд понять:

как идут продажи,

есть ли проблемы в воронке,

требуется ли управленческое вмешательство.

2. Бизнес-вопросы

Перед началом визуализации были зафиксированы ключевые вопросы бизнеса:

Сколько заказов мы получаем?

Есть ли притджение пользователей?

Где именно в воронке происходят потери?

Это разовая флуктуация или устойчивый тренд?

👉 Фокус сознательно сделан на стабильных daily-метриках, а не на real-time данных.

3. Данные

Источник: PostgreSQL
Схема: dm
Витрина: events_v

Основные поля:

event_time — время события

user_id — пользователь

add_to_cart — факт добавления в корзину

create_order — факт создания заказа

Последний день в данных был неполным, поэтому для executive-метрик использовался принцип:

“Вчера vs позавчера”, а не “прямо сейчас”.

4. Логика метрик
🔹 Orders

Что показывает:
Финальный результат бизнеса — количество оформленных заказов.

Формула:

Orders = Sum(if([Create Order], 1, 0))


Использование:

абсолютное значение за день

сравнение с предыдущим днём (trend)

🔹 Users

Что показывает:
Размер входящего потока пользователей.

Формула:

Users = Count(distinct [User ID])


Использование:

оценка спроса

отделение проблем трафика от проблем воронки

🔹 CR View → Cart

Что показывает:
Насколько продукт / ассортимент / UX вызывают интерес.

Формула:

CR View → Cart =
Sum(if([Add To Cart], 1, 0)) / Count

🔹 CR Cart → Order

Что показывает:
Эффективность checkout, оплаты и логистики.

Формула:

CR Cart → Order =
Sum(if([Create Order], 1, 0)) / Sum(if([Add To Cart], 1, 0))

🔹 CR View → Order

Что показывает:
Сквозная эффективность всей воронки.

Формула:

CR View → Order =
Sum(if([Create Order], 1, 0)) / Count

5. Принципы визуализации (почему так)
✔ Daily granularity

минимальный шум

стабильные сравнения

✔ Trend-карточки

значение за “вчера”

% изменение к предыдущему дню

✔ Ограниченный набор метрик

Только то, что:

напрямую связано с деньгами

сигнализирует о проблемах

6. Финальная структура дашборда
🟦 Верхний ряд (основные KPI)

Orders
— факт + Δ к предыдущему дню

Users
— факт + Δ к предыдущему дню

CR View → Cart
— диагностика интереса к продукту

CR View → Order
— итоговая эффективность воронки

🟦 Второй уровень (диагностика)

CR Cart → Order
— используется для поиска проблем в checkout / оплате

7. Пример интерпретации для CEO

“Заказы снизились на 1,7% при стабильном числе пользователей.
CR View → Cart снизился, CR Cart → Order остался стабильным.
Вероятно, проблема на уровне ассортимента или UX, а не оплаты.”

👉 CEO получает понятную гипотезу, а не просто цифры.

В результате был создан:

умеет работать с неполными данными

строит метрики, а не просто графики
